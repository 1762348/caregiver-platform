# 开发路线图

每个阶段都以「可验证的完成标准」收尾，避免出现“代码写完但跑不起来”的状态。

## P0 基建 ✅

- [x] 仓库结构：`backend` / `frontend` / `docs` / `.github`
- [x] 后端骨架：Spring Boot 4、分环境配置、统一响应与异常、`/api/v1/meta`
- [x] 前端骨架：Vue 3 + TS + Vite + Pinia + Router + Vant + Axios 封装
- [x] 首页 / 登录 / 订单 / 我的 / 404 页面骨架
- [x] CI：后端 `mvn verify`、前端 `npm ci && test && build`
- [x] README、架构文档、贡献指南、MIT 许可证

**验收**：干净环境 `mvn verify` 与 `npm run build` 通过；前端首页能显示后端连接状态。

## P1 数据层 ✅

- [x] Flyway `V1__schema.sql`：10 张业务表 + `payment_records`、`order_status_logs`
- [x] `V2__seed.sql`：服务类别、权限、测试账号、示例护工与基础时段
- [x] 实体 / Repository 重写，字段与设计文档对齐（差异见 [design-decisions](design-decisions.md)）
- [x] 测试：迁移与种子数据校验、Repository 查询、名额原子扣减
- [x] 打开 `spring.flyway.enabled`，`ddl-auto` 改为 `validate`

**验收**：H2 空库启动自动建表并通过 `validate`；MySQL 8 重建库后迁移成功；`mvn test` 15 个测试全绿。

## P2 认证授权 ✅

- [x] 短信验证码：`SmsSender` 接口 + Mock 实现（固定验证码、60 秒频控、5 分钟过期、错误次数限制）
- [x] 登录 / 续签 / 当前用户接口
- [x] Spring Security + JWT 过滤器 + 三角色（USER / CAREGIVER / ADMIN）
- [x] 权限码随令牌下发并映射为 authority，支持 `@PreAuthorize`
- [x] 401 / 403 统一 JSON 响应
- [x] 前端登录联调、令牌持久化、路由守卫、个人中心展示

**验收**：未登录 401、伪造令牌 401、验证码错误/频控/过期均有明确提示；三种角色登录后权限正确；
浏览器实测登录 → 首页显示用户名 → 个人中心展示角色 → 清空令牌访问订单页跳转登录。

## P3 核心业务 ✅

- [x] 服务类别、护工列表与详情、排班查询（公开接口，按日期/类别筛选，过滤已满与已开始）
- [x] 预约下单：名额原子扣减、同一被照顾人同时段唯一、订单号生成、创建订单消息
- [x] 支付：`PaymentGateway` 抽象 + Mock 实现、支付流水、回调 HMAC 验签与幂等
- [x] 取消退款：服务开始前 2 小时全额、2 小时内收 20% 手续费、已开始不可取消；释放名额并记状态日志
- [x] 支付超时：定时任务每 60 秒扫描，30 分钟未支付自动取消并释放名额
- [x] 服务进度：护工出发 → 到达 → 开始 → 完成，用户侧按时间戳派生阶段
- [x] 站内消息：预约、支付、取消、进度节点写入，支持未读数/已读/全部已读
- [x] 被照顾人 CRUD + 身份证校验（校验位、出生日期、性别解析）
- [x] 测试：退款规则、订单全流程、并发抢名额、公开目录接口、身份证工具

**验收**：MySQL 实测「登录 → 查排班 → 预约 → 支付 → 取消退款」与「支付 → 护工出发/到达/开始/完成」
两条链路均通过；剩余 1 个名额时 6 个并发请求仅 1 单成功；`mvn test` 50 个测试全绿。

## P4 用户端页面 ✅

- [x] 首页：真实服务类别、进行中订单卡片、未读消息角标、快捷入口
- [x] 四步预约向导：类别 → 日期/时段 → 被照顾人 → 确认，支持后端返回的名称/价格/剩余名额
- [x] 支付：订单详情页选择渠道，支付后刷新状态
- [x] 订单列表（全部/待支付/进行中/已完成/已取消）与订单详情
- [x] 取消订单：确认弹窗 + 退款金额提示
- [x] 服务进度：时间线 + 15 秒轮询
- [x] 被照顾人管理：列表、新增、编辑、删除（身份证校验）
- [x] 消息中心：未读标记、点击已读并跳转、全部已读
- [x] 个人中心入口与路由守卫

**验收**：浏览器实测「登录 → 首页 → 预约 → 支付 → 订单 → 取消」全流程通过；
页面数据全部来自后端接口，无 mock 残留；`npm run test:unit` 14 个测试通过、`npm run build` 通过。

## P5 护工端与管理端 ✅

- [x] 护工工作台：个人资料、今日排班、待服务/服务中统计、按进度操作（出发/到达/开始/完成）
- [x] 护工订单列表：按状态筛选，支持直接更新进度
- [x] 管理后台布局：侧边导航、返回用户端、退出登录（Element Plus 按路由懒加载）
- [x] 服务类别管理：列表、新增、编辑、删除（有护工时禁止删除）
- [x] 护工管理：搜索、状态筛选、新增（自动开通护工账号）、编辑、启用/停用
- [x] 排班管理：按护工/日期查询、批量生成（按基础时段）、单条新增、名额调整、停班、删除
- [x] 停班处理：关闭排班 + 全额退款取消该时段有效订单 + 消息通知
- [x] 角色路由：`/admin/**` 仅管理员、`/caregiver/**` 仅护工，越权跳转对应首页

**验收**：管理员登录后进入 `/admin/categories`，可管理类别/护工/排班；护工登录后进入 `/caregiver`，
看到今日排班与待处理订单；普通用户访问管理端返回 403、访问护工端 403；
`mvn test` 58 个测试通过，前端 14 个单元测试与构建通过。
